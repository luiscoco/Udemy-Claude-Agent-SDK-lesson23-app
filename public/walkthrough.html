01

Annotations are not guards

readOnlyHint permits concurrency but does not guarantee it. The other three hints are descriptive. This app records intervals and labels a 700 ms teaching delay; the reported overlap is an observation, not a benchmark.

02

Controlled error demonstrations

The HTTP 503 endpoint and thrown exception are intentional classroom failures. Both travel through real SDK tool calls. A success query status does not convert the error into successful data. API authentication, budget, process and transport failures can still terminate a run.

03

Original and forwarded results

Handler evidence shows what the function returned. Native-result projections show the SDK user tool_result content after conversion. Image bytes are represented by MIME type and length. The structured-data experiment checks the duplicate-text sentinel directly.

04

Sample chart and inline resource

The bundled PNG uses fixed points 58, 59, 61, 63, 62. It is not weather fetched from Open-Meteo. The report embeds text using a classroom URI. Neither URI access nor file creation is implied.

05

Tool search and process boundaries

This small server uses alwaysLoad for its schemas. Deferred tool search is not demonstrated. In-process describes the custom server, not the Claude Code child runtime or remote model service.

06

Other result types

Audio, resource links and binary resources are reference topics here. Only text, PNG images, inline text resources and structured JSON are executed. Python differs for structuredContent and binary resources; this application teaches TypeScript.

07

Rebuild the sample chart

The PNG is bundled, so Python is not needed to run the app. To regenerate it, install matplotlib in your Python environment and run python scripts/create-chart.py. Keep the classroom-data label.
